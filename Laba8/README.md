### Цель работы
Реализовать итеративный двоичный поиск и хеш-таблицу с разрешением коллизий методом цепочек, а также сравнить время поиска в этих структурах данных.

### 1. Двоичный поиск
Для отсортированного массива целых чисел реализованы две функции:
- `lowerBound` — возвращает индекс первого элемента, который не меньше искомого значения;
- `upperBound` — возвращает индекс первого элемента, который больше искомого значения.

Обе функции используют цикл, поэтому поиск реализован итеративно. Если искомое значение присутствует, его левая позиция равна результату `lowerBound`, а правая — результату `upperBound - 1`.

Сложность каждой функции: **O(log N)** по времени и **O(1)** по дополнительной памяти.

### 2. Хеш-таблица
Реализован класс `HashTable`:
- ключ — `string`;
- значение — `int`;
- коллизии разрешаются методом цепочек.

В каждой ячейке таблицы хранится список пар «ключ — значение».
Реализованы требуемые операции:
- `insert` — добавляет новую пару или обновляет значение существующего ключа;
- `find` — ищет ключ и возвращает найденное значение;
- `remove` — удаляет пару по ключу.

Средняя сложность операций при равномерном распределении хешей — **O(1)**. В худшем случае, когда много ключей попадает в одну цепочку, сложность — **O(N)**.

### 3. Сравнительный анализ
В программе измеряется время поиска для N = 1 000, 10 000 и 100 000 элементов.
Для каждого размера выполняется 100 000 поисковых запросов. В обе структуры заранее помещаются соответствующие ключи. В отсортированном массиве используются целые числа, а в хеш-таблице — их строковое представление.

Программа выводит таблицу с общим временем выполнения поисковых запросов в миллисекундах. Значения времени зависят от компьютера, компилятора и нагрузки системы; для отчёта следует использовать результат собственного запуска.

### 4. Результаты проверки
Проверка двоичного поиска на массиве `1 2 2 2 4 5 7` для значения `2` должна показать:
- левая позиция — `1`;

Также программа проверяет добавление, поиск и удаление ключа в хеш-таблице.

#include <iostream>
#include <vector>
#include <list>
#include <string>
#include <algorithm>
#include <chrono>
#include <iomanip>

using namespace std;
using namespace chrono;

// Итеративный двоичный поиск: возвращает индекс первого элемента >= key.
int lowerBound(const vector<int>& a, int key) {
    int left = 0;
    int right = static_cast<int>(a.size());

    while (left < right) {
        int mid = left + (right - left) / 2;

        if (a[mid] < key) {
            left = mid + 1;
        }
        else {
            right = mid;
        }
    }

    return left;
}

// Возвращает индекс первого элемента > key.
int upperBound(const vector<int>& a, int key) {
    int left = 0;
    int right = static_cast<int>(a.size());

    while (left < right) {
        int mid = left + (right - left) / 2;

        if (a[mid] <= key) {
            left = mid + 1;
        }
        else {
            right = mid;
        }
    }

    return left;
}

// Хеш-таблица: разрешение коллизий методом цепочек.
class HashTable {
private:
    vector<list<pair<string, int>>> table;

    // Вычисление номера корзины для ключа.
    size_t getIndex(const string& key) const {
        return hash<string>{}(key) % table.size();
    }

public:
    explicit HashTable(size_t capacity) : table(capacity) {}

    // Добавление или обновление пары ключ-значение.
    void insert(const string& key, int value) {
        size_t index = getIndex(key);

        for (auto& item : table[index]) {
            if (item.first == key) {
                item.second = value;
                return;
            }
        }

        table[index].push_back({ key, value });
    }

    // Поиск значения по ключу.
    bool find(const string& key, int& value) const {
        size_t index = getIndex(key);

        for (const auto& item : table[index]) {
            if (item.first == key) {
                value = item.second;
                return true;
            }
        }

        return false;
    }

    // Удаление элемента по ключу.
    bool remove(const string& key) {
        size_t index = getIndex(key);

        for (auto it = table[index].begin(); it != table[index].end(); ++it) {
            if (it->first == key) {
                table[index].erase(it);
                return true;
            }
        }

        return false;
    }
};

int main() {
    setlocale(LC_ALL, "ru");
    cout << "Лабораторная работа №8. Двоичный поиск и хеш-таблицы\n";
    cout << "Вариант 5\n\n";

    // Проверка двоичного поиска границ на массиве с повторениями.
    vector<int> example = { 1, 2, 2, 2, 4, 5, 7 };

    int key = 2;
    int leftPosition = lowerBound(example, key);
    int right = upperBound(example, key) - 1;

    cout << "Проверка двоичного поиска:\n";
    cout << "Массив: ";
    for (int x : example) {
        cout << x << ' ';
    }
    cout << "\nЭлемент " << key << ": левая позиция = " << leftPosition
        << ", правая позиция = " << right << "\n\n";

    // Проверка обязательных операций хеш-таблицы.
    HashTable testTable(10);
    testTable.insert("apple", 10);
    testTable.insert("banana", 20);

    int foundValue = 0;
    cout << "Проверка хеш-таблицы:\n";
    if (testTable.find("apple", foundValue)) {
        cout << "Найден apple: " << foundValue << '\n';
    }

    testTable.remove("apple");
    cout << "После удаления apple: "
        << (testTable.find("apple", foundValue) ? "найден" : "не найден")
        << "\n\n";

    // Сравнение времени поиска для N = 1000, 10000, 100000.
    const int searchCount = 100000;

    cout << "Сравнение времени поиска (" << searchCount
        << " повторений):\n";
    cout << "N | Бинарный поиск, мс | Хеш-таблица, мс\n";

    for (int n : {1000, 10000, 100000}) {
        vector<int> numbers(n);
        HashTable hashTable(static_cast<size_t>(n * 2));

        // Заполняем обе структуры одинаковыми логическими ключами.
        for (int i = 0; i < n; ++i) {
            numbers[i] = i;
            hashTable.insert(to_string(i), i);
        }

        // Подготавливаем одинаковые поисковые значения до замера времени.
        vector<int> intQueries(searchCount);
        vector<string> stringQueries(searchCount);

        for (int i = 0; i < searchCount; ++i) {
            int query = (i * 37) % n;
            intQueries[i] = query;
            stringQueries[i] = to_string(query);
        }

        // Измеряем только поиск в отсортированном массиве.
        volatile int binaryResult = 0;
        auto binaryStart = high_resolution_clock::now();

        for (int query : intQueries) {
            int position = lowerBound(numbers, query);

            if (position < n && numbers[position] == query) {
                binaryResult += numbers[position];
            }
        }

        auto binaryFinish = high_resolution_clock::now();

        // Измеряем только поиск в хеш-таблице.
        volatile int hashResult = 0;
        auto hashStart = high_resolution_clock::now();

        for (const string& query : stringQueries) {
            int value = 0;

            if (hashTable.find(query, value)) {
                hashResult += value;
            }
        }

        auto hashFinish = high_resolution_clock::now();

        double binaryTime =
            duration<double, milli>(binaryFinish - binaryStart).count();
        double hashTime =
            duration<double, milli>(hashFinish - hashStart).count();

        cout << n << " | " << fixed << setprecision(3) << binaryTime
            << " | " << hashTime << '\n';
    }

    return 0;
}

### 7. Ответы на контрольные вопросы

**1. Какое условие необходимо для применения двоичного поиска?**

Массив должен быть отсортирован. Тогда после сравнения со средним элементом можно отбросить половину, в которой искомого значения быть не может.

**2. Какова сложность двоичного поиска? Почему она логарифмическая?**

В среднем и худшем случаях сложность равна `O(log N)`, в лучшем — `O(1)`, если элемент сразу находится в середине. На каждом шаге область поиска уменьшается примерно в два раза.

**3. В чём разница между итеративной и рекурсивной реализацией двоичного поиска?**

Итеративная реализация использует цикл, рекурсивная вызывает саму себя для одной из половин массива. Итеративный вариант занимает `O(1)` дополнительной памяти, рекурсивный — `O(log N)` для стека вызовов.

**4. Чем опасен вариант `mid = (left + right) / 2`? Как правильно вычислять середину?**

Сумма `left + right` может переполнить тип `int`. Безопасная формула: `mid = left + (right - left) / 2`.

**5. Что такое хеш-таблица? Из каких компонентов она состоит?**

Хеш-таблица — структура для хранения пар «ключ — значение». Она состоит из хеш-функции, массива корзин (ячеек) и механизма разрешения коллизий.

**6. Какие требования предъявляются к хеш-функции?**

Она должна быть детерминированной: одинаковый ключ даёт одинаковый хеш. Также важны равномерное распределение ключей и быстрое вычисление.

**7. Что такое коллизия в хеш-таблице? Как с ней бороться?**

Коллизия — ситуация, когда разные ключи получают один индекс. Её разрешают методом цепочек или открытой адресацией. В этой работе применяется метод цепочек: элементы с одинаковым индексом хранятся в одном списке.

**8. В чём отличие метода цепочек от открытой адресации?**

При методе цепочек элементы с одинаковым индексом хранятся в списке соответствующей корзины. При открытой адресации все элементы хранятся в самом массиве, а при коллизии ищется другая свободная ячейка.

**9. Что такое первичная и вторичная кластеризация?**

Первичная кластеризация — образование длинных последовательных групп занятых ячеек при линейном пробировании. Вторичная кластеризация — одинаковая последовательность проб у ключей с одинаковым начальным хеш-индексом, например при квадратичном пробировании.

**10. Какова средняя и худшая сложность операций в хеш-таблице?**

При хорошем распределении хешей средняя сложность вставки, поиска и удаления — `O(1)`. В худшем случае, если много ключей попадает в одну цепочку, сложность может достигать `O(N)`.

**11. Когда эффективнее использовать двоичный поиск, а когда — хеш-таблицу?**

Двоичный поиск применяют к отсортированному массиву, когда важен порядок элементов и подходит сложность `O(log N)`. Хеш-таблица удобна для поиска по ключу в среднем за `O(1)`, если порядок не важен.

**12. Что такое коэффициент загрузки хеш-таблицы? Почему он важен?**

Это отношение количества сохранённых элементов к количеству корзин. Он показывает заполненность таблицы. При большом коэффициенте загрузки цепочки могут удлиняться, из-за чего поиск замедляется.

**13. Как работает рехеширование (динамическое расширение хеш-таблицы)?**

Создаётся новая таблица большего размера. Для каждого сохранённого ключа заново вычисляется индекс с учётом нового размера, после чего элемент переносится в новую таблицу. Это позволяет уменьшить длину цепочек.

**14. Как выбрать размер хеш-таблицы? Почему часто выбирают простое число?**

Размер выбирают с учётом ожидаемого количества элементов и допустимого коэффициента загрузки. Простое число часто помогает уменьшить регулярные совпадения индексов при простых схемах хеширования.

**15. Как реализовать хеш-функцию для строк?**

Можно последовательно обрабатывать символы и вычислять хеш, например по формуле `hash = (hash * 31 + код_символа) % размер_таблицы`. В программе используется `std::hash<string>`, а полученный результат преобразуется в индекс по модулю количества корзин.
